discord-pr-triage-guard · sank8-2

Most agents can do the task; this one can be trusted with the side effect.

We didn’t make the model smarter. We made every point and ping conditional, idempotent, and auditable.

The problem

Discord PR points bot

GitHub PR in → award leaderboard points → commit → ping the winner in Discord.

Reading the PR is easy. Trusting the agent with the award and the ping is the hard part.

Failure modes

Side effects go wrong

  • spam Spam PR still gets points and a ping
  • dup Duplicate webhook awards twice
  • inject PR body treated as instructions
  • 429/500 Retry after timeout doubles the write
  • race Concurrent merges double-award

Why not a smarter prompt

Failproof gates the call

PreToolUse runs before the tool. Policy decides. The model never gets a free side effect.

deny › instruct › allow

deny beats instruct beats allow — evidence enriched on every tool call.

Architecture

Evidence → policy → effect

agent → runtime evidence
rules · eligibility · keys → Failproof
PreToolUse gate → award · commit · ping

Policies check facts (rules version, spam, duplicate, approval, commit state) — not the model’s claims.

discord-pr-triage-guard

Four PreToolUse policies

block-award-without-rules No award until fresh rules + eligible PR
block-duplicate-award Idempotency key — no double-award
block-ping-before-commit No ping until commit + verified winner
warn-untrusted-pr-text PR title/body are data, never instructions
